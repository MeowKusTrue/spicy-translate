## 1. Что это за проект

Браузерная утилита (один HTML-файл, ноль зависимостей, открывается локально) для создания **синхронных переводов песен** в формате **TTML** под плагин **Spicy Lyrics** (расширение Spicetify для десктопного Spotify). Цель: взять популярную песню, подтянуть оригинал с таймингами, перевести, **вручную проставить пословную синхру** с волной и хоткеями (в стиле DaVinci Resolve), получить `.ttml`, залить локально в Spicy Lyrics.

Дальняя цель: превратить это в полноценный **редактор субтитров/лирики** с нейросетями и MCP (см. раздел 9).

## 2. Факты про Spicy Lyrics (проверено по их гайдам)

Источники: `guides.spicylyrics.org` (TTML Guide, Uploading and TTML Rules, TTML Tool Feature Reference), `spicylyrics.org`.

- Локальная загрузка: страница песни → **Lyrics Manager → Upload TTML** → выбрать файл → **Temporary Upload** (до смены песни) или **Persistent Upload** (остаётся в локальной библиотеке). После заливки в общую базу рекомендуют чистить кэш Spicy Lyrics.
- **Translation layers в Spicy Lyrics не поддерживаются** (прямо запрещены правилами для аплоада в общую базу). Поэтому наш локальный TTML кладёт **переведённый текст как основную лирику** с оригинальными таймингами. Режим «оригинал + перевод» (перевод как `ttm:role="x-bg"` под основной строкой) экспериментальный, может ложиться криво.
- Один тайминг-режим на файл: line-sync **или** word-sync, смешивать нельзя.
- Пустые строки ломают загрузку файла. Удалять.
- Фоновые строки (`x-bg`): не могут идти подряд, песня не может начинаться с фоновой строки, текст фоновой строки без скобок.
- Правила общей базы (нам нужны как ориентир качества): тайминг слова начинается, когда слышен вокал, и заканчивается, когда он кончился; соседние слова без реальной паузы делят общую границу (конец прошлого = начало следующего); держать реальные паузы; повторы писать полностью; никаких `[Instrumental]` и т.п. **AI-транскрипция и AI-тайминг запрещены для сабмита в общую базу** (локальный файл для себя — не их юрисдикция, но помни об этом, если когда-нибудь будем лить в общую).
- Официальные инструменты: «TTML Tool» и community-форк `tool.community.spicylyrics.org`. Хоткеи у них: `F` начало слова, `G` конец + начало следующего, `H` конец, `A/D` слово, `Space`, `←/→` ±5 с, `[` `]` `'` скорость. Мы их повторяем.
- Непроверенное (проверь, когда понадобится): нужен ли Spotify track ID в локальном TTML, как именно Spicy читает `itunes:key`, songwriters и song-part, как парсит `itunes:timing`.

## 3. Источники текста и таймингов

- **LRCLIB** (`https://lrclib.net`): `GET /api/search?q=...`, `GET /api/get?track_name&artist_name&album_name&duration`. Поля: `trackName, artistName, albumName, duration, syncedLyrics, plainLyrics, instrumental`. Открытый, без ключей, CORS работает из браузера.
- **AMLL TTML DB** (`github.com/Steve-xmh/amll-ttml-db`): пословные TTML, много китайского контента. Статика, индекс `metadata/raw-lyrics-index.jsonl`, файлы в `raw-lyrics/`. Лицензия CC0.
- Другое: Unison, LRCMux, lrc.red, BiniLyrics (перечислены в `spicylyrics/mobile`), Genius (только plain), Musixmatch (лицензированный).
- Аудио: **пользователь приносит свой файл** (drag&drop). Стриминговые сервисы/YouTube не скачиваем и не рипаем — это обход прав, не делаем.

## 5. Модель данных

```js
S.lines = [{
  t, end,          // исходное время строки из LRC (сек), end = следующая строка, максимум t+10
  text,            // оригинал
  tr,              // перевод (строка)
  sync: {          // необязательно; слои синхры по словам
    tr:   [{a, b}|{a:null,b:null}, ...],   // длина = число слов в tr
    orig: [...]                            // длина = число слов в text
  }
}]
```

- Слово = токен по пробелам (`wordList`). Если число слов в тексте слоя изменилось, `sync[layer]` **сбрасывается** (иначе тайминги поедут).
- `getWords(text, sync, t0, t1)`: если слой синхронизирован полностью, берёт реальные тайминги, иначе равномерно «размазывает» слова по длине строки (`splitWords`, веса по длине слова).
- Слой, который идёт в основной текст TTML: `orig` в режиме bilingual, иначе `tr` (если пусто — `orig`). `tr` в bilingual идёт как `x-bg`.
- Автосохранение: `localStorage['proj:<artist - title>']` (только text/tr/sync), аудио в IndexedDB `spicy-translate/audio`. Громкость, магнит, латентность в localStorage.

## 6. Что уже умеет

1. Поиск в LRCLIB, выбор synced-версии. Ручной LRC/plain. Drag&drop `.lrc/.txt`.
2. Drag&drop аудио: имя файла → поиск → автовыбор версии с совпавшей длительностью (±3 с) → волна. Аудио кэшируется по `artist - title`.
3. Перевод: Google (неофициальный `translate.googleapis.com ... client=gtx`, 4 параллельных запроса), копия промпта для LLM и вставка перевода списком (нумерация срезается).
4. Редактор строк: оригинал + поле перевода, клик по времени = перемотка + выбор.
5. **Пословная синхра** (нижняя панель): F/G/H, A/D, Space, ←/→, `[` `]` `'`, undo/redo (200 шагов), Delete сбрасывает слово, поле «реакция, мс» вычитается из момента нажатия, `,` `.` нудж ±10 мс (Shift ±50), L цикл строки, R к началу строки, N магнит.
6. **Волна** (`canvas`, пики 200/с, зум Ctrl+колесо, кнопки +/−/«⤢ строка»): плашки слов, мышиное редактирование «как в DaVinci»:
   - магнит (порог 10 px) к краям других слов, плейхеду и стартам строк, жёлтая направляющая; Ctrl на лету отключает;
   - склеенные границы (разница ≤1.5 мс) рисуются белой перемычкой и тянутся вместе (**roll**); Alt отцепляет и тримит только сторону под курсором;
   - слова не перекрываются (клэмп к соседям);
   - перетаскивание слова целиком: склеенные соседи едут следом, Alt = без следования; призрачные (ещё не размеченные) слова при первом движении «материализуются» из спреда;
   - верхняя полоса: зажать и провести = «нарисовать» время выбранному слову; нижняя часть: тащить = листать, клик = перемотка; ПКМ по слову = проиграть его.
7. Превью в стиле Spicy (караоке по словам, режим translation/bilingual), громкость/mute/скорость, виртуальные часы без аудио.
8. Экспорт: TTML (Word или Line timing, отступ в мс, songwriters), LRC, SRT, проект `.spicy.json` (+ открыть). Копирование через `navigator.clipboard` с fallback на `execCommand`.

### TTML, который мы генерируем

```xml
<tt xmlns="http://www.w3.org/ns/ttml" xmlns:itunes="http://music.apple.com/lyric-ttml-internal"
    xmlns:ttm="http://www.w3.org/ns/ttml#metadata" itunes:timing="Word|Line" xml:lang="ru">
  <head><metadata><ttm:agent type="person" xml:id="v1"/>
    <iTunesMetadata xmlns="http://music.apple.com/lyric-ttml-internal"><songwriters>…</songwriters></iTunesMetadata>
  </metadata></head>
  <body dur="m:ss.mmm"><div begin end>
    <p begin end ttm:agent="v1" itunes:key="L1"><span begin end>слово</span> <span …>слово</span></p>
  </div></body>
</tt>
```
Время в формате `m:ss.mmm`, пробелы между span — текстовые узлы. Пустые строки отфильтровываются. Валидность XML проверяется через `xmllint --noout`.

## 7. Известные ограничения и долги

- Интерфейс вживую в настоящем браузере я (ассистент) не гонял: всё проверено в jsdom со стабом canvas. Отрисовка волны, ощущение от drag и перформанс на длинных треках ждут реального теста.
- Нет настоящего форс-алайнмента: «спред» равномерный, реальную синхру делает человек руками.
- Слова = токены по пробелам; для CJK/тайского нужен сегментатор (`Intl.Segmenter`).
- Одна дорожка (agent `v1`): нет дуэтов, нет `x-bg`-слоя с независимой синхрой, нет `itunes:song-part`.
- Нет мультитрековости (несколько языков одновременно), нет ASS/VTT, нет видеоплеера.
- Google-эндпоинт неофициальный, режется лимитами. Нет глоссария/контекста песни при переводе.
- Undo хранит снимки всей `sync` (JSON) — ок для песен, неэффективно для часовых видео.
- `W.px`-зум и `W.start` не сохраняются между сессиями.
- Цикл строки (`L`) реализован в `frame()` грубо (перемотка при выходе за границу ±0.4 с).

## 8. Как тестировать

Тесты пишутся как отдельные node-скрипты, не лежат в репо (их стоит оформить):
- `node build.js`, затем `node --check` на извлечённый `<script>`.
- **jsdom smoke**: `new JSDOM(html, {runScripts:'dangerously', pretendToBeVisual:true})`, подменить `window.fetch`, стабнуть `HTMLCanvasElement.prototype.getContext` через `Proxy`, задать `clientWidth/clientHeight` и `getBoundingClientRect` у `#wave`. Дальше диспатчить `keydown` с `code: 'KeyF'` и `MouseEvent` на `#wave`/`window`. Внутренний стейт читать через `window.eval('S.lines…')`.
- Проверенные сценарии: хоткеи F/G/H и undo, сохранение/восстановление проекта, автоподбор трека по имени файла, roll/Alt-detach/clamp/магнит/Ctrl-без-магнита/move-with-follow/нудж.
- Экспорт: `xmllint --noout out.ttml`.
- Хочется: Playwright E2E с реальным mp3 (проверка волны, drag, зума), юнит-тесты на `core.js` (vitest).

## 9. Roadmap — что делать дальше

### 9.1. Субтитры и видео (следующий большой шаг)
- Загрузка видео (`<video>`), волна из видео (ffmpeg.wasm или серверный ffmpeg), покадровая навигация, показ сабов поверх видео.
- Форматы: SRT, WebVTT, ASS/SSA (стили, позиционирование), TTML/IMSC, LRC, Spicy-TTML; импорт и экспорт всех.
- Режим «cue-редактор»: таблица cue (старт/конец/текст/стиль/спикер), разбиение/слияние, QC-проверки: CPS (символов/сек), длина строки, мин./макс. длительность, перекрытия, зазор между cue.
- Привязка к смене кадра (shot-change snapping), как в профессиональных тулзах.
- Мультитрек: оригинал + несколько языков, сравнение side-by-side, синхронное редактирование таймингов (ripple для всех дорожек).
- Редактор стилей/спикеров/цветов, шаблоны для YouTube/Netflix-подобных спецификаций.

### 9.2. MCP и нейросети
Идея: вынести тяжёлое в **локальный сервер** (Node/TS или Python) и сделать из проекта **MCP-сервер**, чтобы Claude/другие клиенты могли им управлять, а UI был клиентом того же API.

Предлагаемые MCP-tools:
- `lyrics_search(q)`, `lyrics_get(artist,title,duration)` (LRCLIB, AMLL DB, свой кэш);
- `translate_lines(project_id, target_lang, style, glossary?)` — LLM-перевод **с контекстом всей песни**, сохранением числа строк, учётом слогов/рифмы/слов на строку (чтобы пословная подсветка ложилась), опциональный «две версии на выбор» и back-translation для проверки;
- `transcribe(audio|video)` и `align_words(audio, lines)` — Whisper/WhisperX/Montreal Forced Aligner (Python worker, GPU опционально) для **черновой** пословной синхры; человек дорабатывает руками (помни про правило Spicy: AI-тайминг нельзя в общую базу);
- `separate_vocals(audio)` (Demucs) — чтобы форс-алайнмент работал на чистом вокале, а человек слышал слова лучше;
- `detect_language`, `romanize(lines, lang)` (для японского/корейского/китайского: pykakasi, korean-romanizer, pinyin);
- `qa_check(project_id)` — отчёт по правилам Spicy и субтитровым нормам;
- `export(project_id, format)`, `project_load/save`, `get_state`, `apply_patch(ops)` — чтобы агент мог править тайминги, а не только читать.

UI-интеграции: кнопки «Авто-синхра (черновик)», «Перевести контекстно», «Проверить QC», диф-вью «что изменил ИИ → принять/отклонить» (на базе undo-снимков).

Заметки по LLM-переводу: давать модели всю песню, жанр, исполнителя, глоссарий (имена, сленг), просить сохранять смысл важнее дословности, ограничивать длину строки (слов ≈ слов оригинала ±N), для пословной подсветки просить сохранять порядок образов. Результат возвращать JSON `{lines:[{i, tr}]}` и валидировать число строк.

### 9.3. Архитектура и продукт
- Миграция на **Vite + TypeScript**, разнести на модули (core, store, waveform, sync-engine, exporters, ui), состояние на небольшом сторе с undo на **патчах** (immer/diff), а не на полных снимках.
- Вынести канвас-таймлайн в отдельный компонент с виртуализацией (длинные видео), WebWorker для пиков, `OfflineAudioContext`/`AudioWorklet` для точного аудио-тайминга и компенсации латентности (калибровка «тап в метроном»).
- Упаковка: PWA или **Tauri/Electron** (доступ к ffmpeg, файловой системе, локальным моделям), CLI `spicy-translate export proj.json --format ttml`.
- Локальная Spotify-интеграция: определять текущий трек (Spicetify extension), слать в редактор ID/длительность, чтобы автоподбор текста и версий не гадал по имени файла; кнопка «залить в Spicy Lyrics» без ручного Upload (если у Spicetify есть API для этого — проверить).
- Тесты: vitest на core, Playwright на UI, golden-файлы TTML.

### 9.4. Мелкие улучшения, до которых не дошли

- Выделение нескольких слов (rubberband), групповой сдвиг/растяжение (Time Shift по диапазону), копирование тайминга строки на повтор припева.

- Мини-карта таймлайна, маркеры/комментарии на таймлайне, горячие клавиши с ремапом (как в TTML Tool: Preferences → Keybindings).
