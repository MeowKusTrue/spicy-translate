# auto-align — черновая расстановка таймингов слов (прототип)

Отдельный эксперимент, основной проект не трогает. На вход — аудио песни и проект Spicy Translate
(`.spicy.json`, «Сохранить проект»), на выходе — тот же проект, где у слов основного текста (`sync.orig`)
и бэк-вокала (`sync.bgo`) проставлены примерные тайминги `{a, b, g:1}`. `g:1` = «авто»: в редакторе такие
слова пунктирные, QA о них предупреждает — остаётся пройтись и поправить. Открыть результат: «Открыть проект».

## Как работает

1. **Demucs `htdemucs`** вырезает вокал из микса.
2. **Опционально** модель UVR `UVR_MDXNET_KARA_2` (пакет `audio-separator`) делит вокал на ведущий и бэк.
   Не установлено / не скачалось — шаг пропускается, бэк выравнивается по всему вокалу.
3. **Forced alignment** уже известного текста (не распознавание!): wav2vec2 CTC
   (`jonatasgrosman/wav2vec2-large-xlsr-53-russian` / `-english`, те же, что у WhisperX) + свой Витерби.
   Каждая строка выравнивается только внутри окна `[t − pad, end + pad]` из LRC, поэтому ошибка не
   «уплывает» на соседние строки. По краям окна разрешены «чужие» кадры — там поёт соседняя строка.
4. Бэк-текст (`bg.text`) — то же самое по стему бэка.

Слова считаются **так же, как в редакторе** (`units()` из `src/core/words.ts`): пробелы делят слова,
NBSP склеивает два слова в один блок, `|` делит слово на слоги — каждый слог отдельный блок.
Язык строки — по алфавиту (кириллица → ru, иначе en), можно задать `--lang`.

Что **не трогается**: слой, целиком размеченный вручную (все слова с `a`/`b` и без `g`), и отдельные
ручные слова в частично размеченном слое. Начало/конец строк (`t`/`end`) и перевод не меняются.

## Установка

Нужны Python 3.10–3.12 и `ffmpeg` в PATH.

```bash
cd experiments/auto-align
py -3.12 -m venv .venv
```

```bash
.venv/Scripts/python -m pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu124
```

Без видеокарты вместо этого: `--index-url https://download.pytorch.org/whl/cpu`.

```bash
.venv/Scripts/python -m pip install -r requirements.txt
```

`audio-separator[cpu]` в requirements — необязательный (разделение лид/бэк). Для GPU поставь
`audio-separator[gpu]`, можно вообще не ставить. Модели (~1.3 ГБ wav2vec2, ~80 МБ Demucs, ~50 МБ
karaoke) скачиваются при первом запуске в кэш HuggingFace / torch.

## Запуск

```bash
.venv/Scripts/python align.py song.mp3 project.spicy.json -o out.spicy.json
```

Флаги: `--device cuda|cpu` (по умолчанию cuda, если есть), `--lang ru|en`, `--pad 1.5` (запас окна
вокруг строки, с), `--model <HF id>` (другая wav2vec2 CTC модель), `--no-separation` (а капелла),
`--no-karaoke`, `--force` (перевыровнять и ручные слои тоже — и напечатать ошибку относительно них).

Стемы кэшируются в `out.stems/` рядом с выходным файлом — повторный запуск не гоняет Demucs заново.

### Проверить точность на своей песне

Возьми проект, где строки уже размечены вручную, и:

```bash
.venv/Scripts/python align.py song.mp3 hand.spicy.json -o auto.spicy.json --force
```

Скрипт напечатает медиану / p90 ошибки начала слова отдельно для `orig` и `bgo`.

## Проверки

- `python test_align.py` — без моделей и аудио: правило `units()`, Витерби на синтетических
  вероятностях (строка среди соседних), сохранение ручных слов, bg-only строки.
- `python bench_tts.py` (Windows) — сквозной прогон всего конвейера: голоса Windows TTS (Irina — лид,
  Pavel — бэк, бэк налезает на хвост лида) поверх фейкового «минуса» из аккордов и шума, точные начала
  слов от SAPI как эталон. Результат — `sample/tts_auto.spicy.json`.

### Результат

Настоящей песни с ручной разметкой для замера не было — замер только на TTS-речи (это не пение, на
вокале ошибка будет больше):

| слой | слов | медиана ошибки начала | p90 | ≤ 200 мс |
|---|---|---|---|---|
| лид `orig` | 26 | 60 мс | 71 мс | 100 % |
| бэк `bgo` | 8 | 43 мс | 64 мс | 100 % |

(RTX 4060 и CPU дают одно и то же; 26 с аудио: wav2vec2 на CPU ~30 с.) Ошибка почти целиком —
постоянный сдвиг: авто-начало на ~60 мс позже, чем отметка SAPI.

Karaoke-модель на этом тесте **не сработала**: два моно-голоса TTS она целиком отнесла к лиду, стем бэка
вышел почти пустым, и бэк сначала встал мимо (медиана 1.2 с). Поэтому теперь, если в окне строки стем бэка
тише 10 % от вокала (`BACK_MIN`), бэк выравнивается по всему вокалу — это и дало 43 мс. На настоящих песнях
(бэк обычно в стерео, с ревером) разделение должно работать лучше, но это **не проверено**.

## Ограничения

- Это **черновик для проверки**, не готовая разметка. Пение (растянутые гласные, мелизмы, крик, эффекты)
  wav2vec2 видит хуже речи; ошибка на реальных песнях — проверь на своей через `--force`.
- Конец слова `b` эвристический: последняя буква + 0.3 с, но не дальше начала следующего слова.
- Слова без букв (`—`, цифры) получают 0.2 с рядом с соседом.
- Слоги (`при|вет`) выравниваются по своим буквам — нормально для длинных слогов, грубо для коротких.
- Повтор одной и той же фразы в соседних строках при большом `--pad` может «прыгнуть» на соседнюю —
  тогда уменьши `--pad`.
- Бэк, поющий одновременно с лидом тот же текст, без karaoke-модели выравнивается плохо.
- Смешанный текст (английские слова в русской строке): буквы чужого алфавита пропускаются, такие слова
  встают между соседями.
