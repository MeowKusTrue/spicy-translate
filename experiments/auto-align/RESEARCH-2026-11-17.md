# Пропуски строк: исследование 17 ноября 2026

## Результат

Для известного текста основной кандидат на улучшение — прямое выравнивание
пропущенных фраз по вокалу с контекстом соседних строк, а не обязательное
повторное распознавание каждого слова. Менять wav2vec2 на Qwen по умолчанию
текущий локальный замер не обосновывает.

Исследование выполнено 17 ноября; его результаты ниже описывают состояние
до реализации. 18 ноября для 1.8.7 добавлено восстановление в окнах до 30 с
с проверкой соседних опор. Кандидаты предлагаются в отдельном окне проверки,
применяются только по выбору пользователя. На полном прогоне исходного
проблемного трека получено 17 кандидатов из 45 пропусков. Открытый проект
не менялся. Глобальное CTC для длинных участков пока не добавлено.

## Что происходит в 1.8.6

В исследованном результате 114 строк: 111 с основным текстом и 3 без него.
66 строк получили расстановку, для 45 строк основного текста не найдено опор.
Это пропуск этапа определения окна, а не авария Python из предыдущей версии.

`line_windows._ordered_windows` требует совпадения первого и последнего
токена и покрытия не менее 80% текста. Затем проверяет единственность
расположения среди лучших монотонных решений. Если Whisper пропустил слово
на краю или повтор припева, строка может не пройти этот этап. В `run` функция
`aligned_for` возвращает `None` для строки без опоры: акустическое
выравнивание её готового текста даже не пробуется.

  распознавании лирика не получает надёжного времени. Проект перешёл к
  выравниванию готового текста и singing fine-tune
  [tuneperfect/tunestudio-aligner](https://huggingface.co/tuneperfect/tunestudio-aligner).
  Авторы сообщают о снижении доли ошибок более 500 мс с 56,6% до 6,8%
  на шести эталонных песнях. Это **их** тест, только английский; модель
  обучалась на английских и немецких данных. На русском здесь не проверена.
  Веса имеют CC-BY-NC-4.0; перед включением требуется учесть условия модели.
- [utasub](https://github.com/nnyj/utasub#alignment).
  Использует глобальное упорядоченное CTC-выравнивание MMS с `<star>` для

  архитектура для повторов и длинных пробелов между опорами; сам README
  отмечает возможность ошибочного размещения. Заявления о пригодности
  этого приложения для русского здесь не делаются.
- [Qwen3-ASR / ForcedAligner](https://github.com/QwenLM/Qwen3-ASR).
  Официально поддерживает русский. Singing указан для ASR; область
  forced aligner в таблице — Speech. Проверен именно
  [нативный Transformers checkpoint](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B-hf),
  revision `c07281df297b9905d24a508279258cccf987a064`.
- [audo](https://github.com/josh-romer/audo).
  Пример локального караоке-конвейера RoFormer → Qwen3-ForcedAligner →

  для пения; наличие готового конвейера не доказывает точность на нашем наборе.

## Проба на текущем проблемном треке

Из локального кэша прочитаны вокал и предыдущий результат. Проверены четыре
участка с пропущенными строками: 4; 8; 11–12; 49–53 — всего девять строк.
В каждое окно включены две соседние успешно найденные строки и запас 0,4 с.
Окна длились примерно 8,8–20,3 с. Никакие значения из прогона в проект не
применялись.

Оба имеющихся CTC-движка (wav2vec2 и MMS) дали кандидаты для всех девяти
строк. Границы строк были близки, но оценка вероятности букв на припеве
49–53 сильно отличалась. Эти значения не являются калиброванной
вероятностью правильного тайминга и между разными моделями напрямую
несопоставимы. У Qwen на тех же четырёх окнах шесть слов получили нулевую
длительность: одно в окне 11–12 и пять в окне 49–53, включая контекст.

**Заполненные тайминги не равны верным таймингам.** Для этих девяти строк
нет независимой ручной разметки, поэтому улучшение точности не измерено.
Проба подтверждает возможность получить акустические кандидаты там, где
ASR-сопоставление сейчас полностью прекращает обработку.

## Сравнение с сохранённой ручной разметкой

Локальный набор: четыре разметки из `bench/`, две относятся к вариантам
одной песни. 1055 начал слов основного вокала; слоги объединены в слова.
Сравнивались одинаковые слова и одинаковые вокальные дорожки HTDemucs.
Каждая строка получила существующее окно `t/end` с запасом 1,5 с.
CTC сохранял обычный штраф вне исходных границ; Qwen получил тот же аудиофрагмент.
Это сравнение существующих способов применения, а не изолированный рейтинг
архитектур моделей. Бэки, точность слогов и поиск строк по всей песне не оценивались.

Неверные/нулевые/выходящие за окно предсказания и отсутствующие результаты
учитываются как промахи в процентных показателях. Медиана и p90 ниже
вычислены только для валидных предсказаний; столбец количества показывает
их знаменатель. Одна многотокенная группа исключена из общей выборки
одинаково для всех движков из-за несовпадения единиц токенизации.

## Рекомендуемое изменение приложения

1. Сохранить точное CTC-выравнивание wav2vec2 для основного русского текста.
2. После поиска надёжных опор пробовать прямое выравнивание пропущенных
   строк совместно с соседними фразами в ограниченном аудиоокне. Не
   требовать, чтобы Whisper заново узнал каждое слово.
3. Для длинных участков без опор отдельно проверить глобальное CTC с
   промежутками между фразами. Порядок строк и ручные опоры должны
   ограничивать выбор конкретного повтора; распределение по времени
   само по себе не является доказательством совпадения с вокалом.
4. Сомнительные кандидаты показывать для прослушивания с номером и
   текстом строки, выбранным участком аудио и возможностью принять/оставить
   прежнее. Ручную разметку и одобренные слова сохранять.
5. Перед автоматическим принятием новых кандидатов измерить ошибки
   восстановления искусственно скрытых опор на ручном наборе, включая
   повторяющиеся припевы, неверный/неполный текст, длинные паузы и бэки.
   Отдельно разметить проблемные участки текущего трека. Не подбирать порог
   только ради увеличения количества заполненных строк.

Нативный Qwen в проверенной конфигурации не выбран заменой по умолчанию.
Tune Studio остаётся кандидатом на отдельное сравнение на русском;
его singing fine-tune в этом исследовании не запускался.
